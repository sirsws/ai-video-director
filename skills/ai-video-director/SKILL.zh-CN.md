# AI 视频导演

创作有具体观看回报、人物或形式有记忆点的短视频作品，交付适合本次生成入口的制作包。传播判断要指向片中的实际过程与回报，不能把设计评价当成已验证效果。

## 使用条件

沿用本次要求及所在项目的 AGENTS.md、其明确引用的配置和 Brief；个人形象、创作口味、图库、目录与平台设置由项目提供。本 Skill 不依赖特定项目文件；视频模型、平台和时长按任务确定，通用创作方法不绑定特定生成器。

只核对会影响本次执行的条件：生成平台与具体入口、可用时长和画幅、支持的素材与身份绑定方式，以及本轮只交文字、制作包还是执行工具。已知条件直接沿用；只在缺项会改变当前设计或操作时提问。未指定人物时按作品需要设计角色，不默认用户出镜。使用即梦／Seedance 时按需读[入口适配](references/platforms/jimeng-seedance.md)，不把 APP、网页与 API 能力互相套用。

参考图按本轮范围交完整制图词、复用已有素材，或用已授权且可用的生图工具制作；不以完成制作包为由擅自调用生成服务。裁切、格式转换与 Alpha 等确定性处理用本地工具并保留原图。未提供或确认生成入口时，可先完成通用声画设计，不虚构上传语法或可选设置。

审片按宿主实际能力取证；不能审听时，听感采用用户明确反馈，机器转写与音轨参数不能代替听审。拆帧、测试、缓存与蒙版预览放系统临时目录。

## 任务接入

从请求和现有材料识别：已有方向、故事、拍法、提示词还是实际视频；本次做新作、深化、局部修改、诊断或剪辑；用户已定要求及可改范围。已有信息直接沿用，只问会改变核心意图或当前执行、且无法从材料解决的缺项。

所有构想、拍法和提示词都进入作品创作，已有内容是继续完善的起点。已有稿的局部修改只核对原意与受影响决定，直接按[局部返修](references/production-and-delivery.md#local-revision)处理。实际视频先查看，不能从原提示词推定视频已实现。

收到反馈时，先判断问题在作品看点、具体拍法、参考输入还是实际生成。看点或人物关系本身不足，回到作品创作完善相应决定，不只扩大场面或增加形容词；原有体验已经成立而局部表现有问题，按局部返修处理，保留未受影响的内容。

## 主流程

**任务接入 → 作品创作 → 生成准备 → 检查与交付制作包。**

1. 读[作品创作](references/creative.md)，先确定本片主要的观看体验，写清观众具体会看见或听见什么，以及吸引力怎样从过程中产生。内容、表演、摄影、节奏与声音围绕同一体验共同设计；类型方法按[方法调用](references/creative.md#method-use)取用。
2. 全新方向先给少量包含主要过程、关键拍法和观看回报的不同构想，由用户选定；已有选定方向直接深化。用户授权自主选定时自行比较并推进。方向选定后，继续把本片所需的动作、互动、摄影和声音发展成可连续观看的过程；若照方案完整实现仍不能体现用户所求的体验，先完善相关决定，再进入生成准备。随后连续完成制作包，不再默认等待导演或图片方案确认。
3. 读[生成准备与交付](references/production-and-delivery.md)，先明确参考输入需要补充哪些信息，再按需选择文字、已有素材或新图；核对所选图片提供的信息，以及可能带入的姿态、布局或状态干扰。形成与实际输入相容的提示词，检查正文、素材绑定和上传清单是否落实已定方案，再交付。需要改变用户锁定要求或执行范围时再交由用户决定。

用户当场要求“先看构想”“先看拍法”“暂不出图”“只要提示词”时，按本次范围执行。只要正文仍须完成必要创作与输入检查，其他交付内容沿用本次范围。

<a id="delivery-status"></a>

按本轮约定交齐后，记录本轮制作包或文字稿已完成；有项目索引时按项目规则登记，不自动设立等待生成、等待回传或定时跟进任务。制作包完成不代表成片已生成或验收。用户之后提供实际视频并要求后期处理，进入[可选后期](references/post-production.md)：**素材审看与剪辑方案 → 剪辑执行 → 检查与交付成片**。原片保留；制作包完成与后期成片完成分别记录。

## 按任务读取

| 当前需要 | 读取位置与作用 |
| --- | --- |
| 一句话、已有构想、拍法、提示词 | [作品创作](references/creative.md)：共同发展内容和声画；[25类方法入口](references/methods.md)按问题找随包方法。 |
| 具体摄影、表演、光色、声音或动态关系 | [技法索引](references/techniques/INDEX.md)；整体处理、场面拍法和结束用途查[拍摄处理](references/shooting-treatment.md)。 |
| 参考输入选择或制作 | [图片用途与取舍](references/reference-images.md#reference-selection)；需要图片时再读对应制作/验收部分。项目提供图库时先定向查适用资产。 |
| 用户指定参考作品或回传视频 | [参考视频](references/reference-videos.md)：实际查看过程，区分原作事实、用户描述和本次设计；已有充分分析可复用。 |
| 多个片段、下一段接续 | [连续片段](references/sequence-and-continuation.md)：全片计划与实际采用状态分开，在同一作品材料更新。 |
| 比赛、品牌或官方作业 | 叠加本次提供的工作流与 Brief，核对提交要求；历史特例不推广。 |
| 检查、平台反馈、局部返修 | [问题处理](references/production-and-delivery.md#repair-decision)：先取证，再修相关决定、正文或素材。仅要分析时不自动执行修改。 |

采用具体作品、模板或原提示词时，按[参考选择与改编](references/reference-adaptation.md)取用；项目已提供索引和来源范围时遵循其约定。外部材料不接管本流程，不因使用 Skill 遍历历史交付或私人案例。随包方法可直接使用，无须先下载外部仓库。

## 文件与旧作

保存位置沿用用户或项目约定；没有保存要求时直接在对话交付，不预设私人目录或索引。交付格式、文件及连续作品与旧作的更新方式按[交付与记录](references/production-and-delivery.md#delivery)执行。

检查以本次目标和具体证据为准；无新问题可以维持原稿。一次生成失败不自动要求重构，一次被接受也不证明稳定成功率。
