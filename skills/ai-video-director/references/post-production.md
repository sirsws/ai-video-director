# 回传视频的可选后期

用户提供实际视频并要求剪辑时读取。已有制作包时直接承接同一作品；成片长度按本次目标决定，不套用生成器单次时长限制。直接承接已授权的剪辑工作，不增加默认审批环节。

## 素材审看与剪辑方案

先找本次实际采用的视频与现有作品文件。旧栏目中的“最终创意”和“拍摄设计”共同提供作品意图；有新要求时按[作品创作](creative.md)更新受影响决定，不重新发散整片。

用 ffprobe 核对实际文件的时长、画幅、帧率和音轨；按[视频查看方法](reference-videos.md)查看主要过程及关键区间，需要对白时间时用其中的本地转写。文件名、旧提示词、生成任务记录不能证明片中有什么。技术探测、稀疏抽帧与完整运动观察分别记录，不补造看过或听过的内容。

先找可用区间，再选叙事入出点：

- 可用区间说明哪里有实际缺陷、哪里足以承载动作或表演；停顿、黑场、静止不因其形式自动判为瑕疵。
- 入出点说明为何在这里进入和离开。保留必要的起势、动作、接触、反应和对白，不能为避开小瑕疵把主要过程剪没。声音完整而画面局部不可用时，可评估保留声音、另接已有画面。
- 按[剪辑与连续性](techniques/editing-and-continuity.md)处理动作方向、状态、信息和声音接缝；不自动增加快切、变速、转场、配乐或调色。
- 素材缺少必要内容时，按[返修选择](production-and-delivery.md#repair-decision)定位需补的片段；不能靠重复、静帧或裁掉要求冒充完成。

剪辑单使用实际源时间，沿用已有后期记录或在对话中说明。小任务一段文字即可；多段时用下表，只有用到的栏目才填：

| 顺序 | 实际源文件与入—出点 | 保留的过程／切点理由 | 成片位置 | 声音、字幕或其他处理 |
|---|---|---|---|---|
| 1 | 本次采用片段，源内秒数 | 如完整保留起跑到落脚 | 成片起止 | 原声随画面；必要声点位置 |

字幕以用户认可的文字或剧本为准，ASR 用于定位与核对，不据错词改对白。歌曲、音乐与对白不能仅凭音轨存在判断内容正确。宿主不能主观审听时，涉及实际听感沿用用户明确反馈。

## 本地执行

精确修剪、顺序拼接、普通中文字幕、原声同步和附加声部时间安排使用 [edit_video.py](../scripts/edit_video.py)。它只执行明确剪辑单，不选择切点或决定创作。

原视频保留，输出选新版本名。脚本使用 `-n` 拒绝覆盖已有成片及其执行记录；原声随切点重新编码，不能称为音频字节不变。默认保持首段探测到的画幅和帧率、首个声音源的采样率；所有声音源均单声道才输出单声道，否则输出双声道。源画幅不同须明确选输出画幅，按完整画面缩放留边，不自动裁切。无需固定像素、帧率或响度来“提升质量”。

### 执行文件

将剪辑决定写成 UTF-8 JSON。源路径可为绝对路径，或相对于该 JSON 的路径；`in/out` 为源内秒数，`out` 不包含该时刻。以下是两段原声拼接，并在成片第二段显示字幕、2.5 秒加入短声音的示例；实际任务按真实选段替换，不默认附加声音：

```json
{
  "cuts": [
    {"source": "原片A.mp4", "in": 0.52, "out": 2.52},
    {"source": "原片B.mp4", "in": 1.04, "out": 3.04}
  ],
  "subtitles": [
    {"start": 2, "end": 3.5, "text": "用户认可的字幕"}
  ],
  "font_file": "字体/本机实际可用的中文字体.ttf",
  "font_size": 34,
  "audio": [
    {"source": "声音.wav", "in": 0, "out": 0.5, "at": 2.5, "gain": 0.5}
  ]
}
```

不用字幕时省略 `subtitles/font_file/font_size`；不用附加声音时省略 `audio`。需要改变某段原声音量时，该 cut 可加 `audio_gain`，默认 1，0 为明确静音。附加声音的 `at` 是成片时间，`gain` 是线性音量；`in/out` 按选中音轨自身时长核对，不用较长的视频或容器时长补足声音，音轨时长无法确认时转专项处理。它与原声叠加，不默认压低原声、限幅或归一化，安排重叠声部时须核对峰值并按需要调音量。

需要统一画幅时显式写 `"size": [1080, 1920]` 等本次值。`fps` 可显式约束为与源一致的帧率；各源帧率不同或需要改变帧率时用专项 FFmpeg 命令，脚本不静默补帧。入出点按最近源帧对齐，恰好半帧时向后，记录同时保留请求时间和实际时间，音画共享同一段长。选点尽量用已看过的源帧位置，核对量化是否影响动作或声音。脚本重新编码精确选段，不将 stream copy 当成精确到帧的修剪。

字幕字体必须指向本机实际存在且支持中文字形的文件。先核实路径；示例字体不在机器上时换真实字体，不依赖 Windows 默认 Fontconfig 自动匹配。脚本把字体和字幕文本放在临时目录，避免盘符、中文路径和文本符号破坏 FFmpeg 滤镜参数。

脚本需要 Python、FFmpeg 与 ffprobe；使用字幕还需本机支持中文字形的字体。先核对所需工具，不能把示例路径当作已安装位置。在任意工作目录运行，脚本、输入和输出均换成实际绝对路径：

```powershell
python -X utf8 "<本 Skill 根目录>/scripts/edit_video.py" "<作品目录>/剪辑计划.json" "<作品目录>/成片-v1.mp4"
```

脚本输出 H.264/AAC MP4 与同名 `.edit.json`，记录源哈希、请求与实际切点、成片参数、实际视频帧数及完整解码结果。源内可用范围以视频帧为准，音轨更长不等于还有画面；输入与输出均核对真实帧时间，不只凭平均帧率判断恒定帧率。无音轨片段可为拼接补技术静音轨，不把它记为原片有环境声。报错时保留源与已有结果，先定位原因，修订后用新版本名，不把失败残片当成片。

脚本覆盖起始时基为零、帧率一致的常规恒定帧率、单视频流、单原声音轨和单／双声道。非零 `start_time`、可变／混合帧率、多音轨选择、多声道、非方形像素、特殊字幕排版、精细调色、变速或复杂转场需要单独编写 FFmpeg 命令或使用对应编辑工具；说明实际执行参数，仍遵循原片保留、明确时间映射与导出核验。不要为这些偶发需要扩大常规脚本。

## 导出检查与交付

脚本完成后仍需查看真实成片，不能把进程成功视为内容验收：

1. 读执行结果，确认实际时长、画幅/fps、音轨与目标一致，完整解码无错，源文件未被修改。使用自写 FFmpeg 命令时也完成这些核对。
2. 查看片头、主要动作、所有关键切点两侧、片尾及字幕起止，核对必要过程、动作方向、画面完整性与字幕字形/遮挡。切点有疑问时逐帧看该区间，不只看一张缩略图。
3. 声音分开说明音轨/时长/峰值等技术结果、机器转写与用户听感反馈。需要技术检查时可用 FFmpeg 的 `astats`、`ebur128` 或 `volumedetect`；数值不能证明对白、音乐、音色和听感正确，也不自动触发响度调整。
4. 实际输出与剪辑单不符就修受影响处；如果核心过程无法由现有素材完成，如实记录缺口并选择局部返修，不降低标准宣布完成。

交付成片、剪辑单或执行 JSON、必要的字幕/工程文件，并在已有后期记录或对话中说明当前成片结论和未测项。保留制作包已完成的事实，后期另记已完成或具体未解决内容，不改成默认等待回传。聊天提供成片链接、关键变化和影响使用的限制，不复述全部技术日志。
