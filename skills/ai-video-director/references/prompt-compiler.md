# 提示词编译

<a id="从拍摄设计编译"></a>

## 适用范围与继承原则

首次编写或本次要求整体重写提示词时读取。已有稿局部修改先按[局部返修](production-and-delivery.md#local-revision)处理，仅查受影响的表达方法。设计缺口回到同一方案修正；本文件负责实际输入的表达，不另开创作阶段。

沿用[生成准备](production-and-delivery.md#compile)已定的镜头与输入方案，包括采用的预演调整。编译面向最终提交的参考图、身份绑定与正文：图已清楚提供的内容按用途绑定，图外空间、动作所需条件及摄影变化用文字落实；不能引用导演稿、灰模或检查结论代替生成描述。尚未出图时按已定制图方案编写，出图后按实际图片复核；素材执行与交付顺序由主流程维护。

编译沿用核心体验、必要成立条件、允许自然变化的表演细节、参考用途与状态，以及各段开始、推进、结束和承接的视听关系。可补齐不改变观看效果的实现参数。若编译中发现设计缺口，直接修改对应镜头及关联输入；核心内容与回报需要改变时，回到同一作品方案的相关决定；涉及用户锁定要求按总入口处理。

沿用拍摄设计已选的技巧与已读材料；只有具体表达存在缺口时，再补读相关小节。已知条目直接进入，不重读索引；尚未定位时再查[视听技巧索引](techniques/INDEX.md)。

## 人物与参考输入绑定

<a id="reference-input"></a>

### 按输入用途组织信息

- 方案确定无需上传参考素材时，用文字给出必要的主体、场景、影像与初始状态，再写动作、镜头和声音过程。需要但尚未生成的图片仍按已定方案编写引用，未生成状态在对话中说明。仅作分析依据的素材，把所借用的可观察关系译成这些文字，不放入上传变量。
- 有参考图时，沿用并核对已确认用途及当前界面的引用方式。图片按指定用途提供可见属性或状态，不从外观、表情或姿势擅自推定未指定的剧情身份、人物关系、行动意图、道具归属或事件结果。提示词仅对明确作为首帧的图声明开场构图继承；单张图也可以只是造型或场景参考，不凭数量判定用途。这是用途声明，其他可见内容仍可能影响生成，需核对关键冲突。
- 以最终实际上传的图片判断哪些信息已由视觉承担，不重复铺陈仍清楚可见的内容。裁切、抠头或其他处理移除了本片所需的造型、状态或关系依据时，由其余实际输入或视频文字补足；完整头区透明不改变数字分身的身份引用写法，本片需要的妆面、头部朝向、表情等状态和变化仍按具体镜头表达。文字同时组织运动、镜头、声音和时间关系，多图逐一绑定用途。

图片用作当前起点时，从图中实际状态继续。保持当前时刻时，安排本片需要的呼吸、观察、环境或持续活动，只锁必须稳定的属性；发生反应或变化时，写清触发、行动展开与后态。不中断用户要求的大动作，也不固定微动作数量或反应秒数；起点已位于事件中途时，不重演前因。

采用顺序分镜参考图时，承接[逐格校准](reference-images.md#出图后逐格校准)的结果，用图号与格号或明确位置绑定对应片段，说明图示为开始、途中还是结束，落实该段动作、摄影、声音及前后衔接。图示为中途或结束目标时，写清如何到达，不默认从该图状态起演；按实际片段组织正文，格数不决定切镜数。未出图的文本包依据计划编写，不能当作已按实图校准。

当前入口支持视频等参考输入时，使用该界面实际标签，分别写选中对象、控制维度和不迁移的内容。例如只取已核对人物的脚步顺序，就写明身份与服装另按本片设定、摄影另按本片机位；不能把“只参考动作”同时解释为继承镜头运动。入口未支持、素材不存在或仅有用户描述时，正文按文字设计写，在对话中说明依据和限制，不造出已上传的视频标签。

首尾帧输入已支持且素材已具备时，分别声明起点与最终视觉目标，编译两者之间实际要发生的连续过程、摄影与声画变化、必须保留的关系。不是风格参考，也不是把两个画面并列后让模型猜中间。尚无图片或输入方式未确认时，可以交两端的文字设计及当前可用正文，在对话中说明适用条件，不声明已执行首尾帧操作。

参考输入声明只写生成所需的绑定和视听要求。图片是否已生成、是否检查通过、潜在影响分析与使用前准备，在对话中说明；完整文本包中的最终视频提示词同样按准备好素材后可直接使用的形式编写，不把“计划中的图片”或内部验收结论写进生成正文。

<a id="视频提示词编译"></a>

### 人物、道具与变量

角色与素材绑定沿用本次入口及项目约定；普通 AI 人物不需要数字分身账号。以下变量是可选写法，界面素材标签必须用实际值，不能把变量约定当作平台通用语法。

- 每份实际使用或计划上传的参考输入只定义一次；图片例如 `{人物图}=参考图1`、`{场景图}=参考图2`，其他媒介仅在当前入口支持时绑定其实际标签，不凭示例造语法。素材变量不反向引用尚未定义的角色，用途及多主体素材中选中谁，在后面的角色、道具或场景绑定中表达。
- 角色用 `{主角}`、`{女巫}` 等可辨且稳定的变量，也可用 `{主角1}`、`{主角2}`。采用数字分身时，只绑定当前入口实际支持、且本次选定的身份标签；即梦标签的使用见[入口适配](platforms/jimeng-seedance.md)。有衣装参考时说明身体服装按哪张图，无图时用文字说明必要衣装，不把示例账号当作固定标签。已有普通 AI 角色参考图时，直接写“按{人物图}的……”，按图片实际用途与可见内容绑定面孔、服装或整体造型；仅有服装图时不据此绑定面孔。文字补足图片未提供但本片需要的信息与已确认的变化，不用简略外貌词替代已有图设。无图的独立 AI 角色用文字给出可辨的体型、面貌、服饰与气质；群演可用数量和统一形象定义。角色出现在手机、监控等画面内时，明确外部空间与屏幕内各自的角色、动作，以及屏幕持续显示谁的时段。
- 道具需要独立追踪时，在对应图与持有者定义后绑定，例如 `{战斧}=按{机体图}的宽刃月牙重斧，全程由{机甲}右手持握`。只定义实际使用的变量，不按示例凑角色或道具。
- 后文的动作、对白、造型与场景说明统一使用已定义变量，不交替使用裸图号、分身标签或新的变量别名。普通物件不必全部变量化；凡使用变量，必须先定义、后引用，每个变量只指向一个对象。

`〈〉` 是必须替换或删除的模板槽位；`{}` 是正文变量的命名约定，不保证模型按程序展开。变量定义用于辨认对象、绑定素材及约定稳定属性与归属。人物与道具的相对位置、支撑和朝向属于场面关系；表情、姿态、睡醒、持物变化等属于阶段状态，分别在初始场景或对应过程表达，不混作人物的固有属性。全程固定的持有关系仍可统一约定。发生[结构或形态变化](techniques/spacetime-effects.md#structural-change)后，明确延续变化后的状态，避免旧定义与新状态冲突。

## 场景、风格与声画过程

### 场景与整体影像

场景给出行动开始时的空间与状态，视听过程要承接这些条件，写清动作中哪些关系维持、哪些发生改变。对会因对象、朝向、路径、支撑或先后不明而变成另一动作的地方，把其成立所需的关系与动作连成可理解的过程，不能只凭变量名或场景段出现过相关词句，就认定承接已完成。只落实本次动作依赖的关系，固定外观和通用美术不随镜重抄。若无法说明怎样发生，或先后过程挤不进可用时长，回到拍摄设计解决，不靠重复设定或堆细节填补。

【视觉风格】集中表达整体影像类型、光线与色彩、人物和衣料质感、环境层次、摄影与运动观感及必要的一致性要求，可用自然语言或清楚的关键词列表。原【画质】中的清晰对象、对焦、纹理及有意柔化等要求可合入此处，确需突出时也可单列。整体风格表达如“柔和轮廓光”“自然发丝运动”“适度运动模糊”可以直接保留，不必逐项扩写成光源坐标、运动轨迹或逐镜参数；只有影响本片关键效果或存在具体冲突时才进一步限定。具体动作和切镜写在【视听过程】。

### 动作、时间与衔接

正文可按连续自然段、镜头、时间段或音乐段落组织，写清事件先后与动作承接，不固定镜头数。分段依据是观看变化，不是均匀切秒；时间段边界不自动意味着切镜、停顿或动作重启，时间戳也不是精确控制保证。连续打斗、舞蹈和演奏先写清整体推进，将导演已定的关键节点及其成立所需的衔接过程写入正文，不默认逐拍拆解。用户指定或观看效果依赖的拍点须保留动作、声音、运镜或特效的对应关系；细微先后用动作触发与相对顺序表达，其余过程可连续描述。

段落延续导演已定的动作、信息或情绪过程，持续表演与等待不必强行增加可见结果。

本段时长按当前任务与入口确定；需要用户另行设置的参数在视频正文前简要标注，已由设置承担的参数不在正文反复声明。用于组织观看节奏的时间段可按需要保留。

### 摄影与声音

按[运镜与取景](techniques/camera-foundations.md#camera-move)落实导演已定的观察位置、观看方向、速度与停顿，以及途中显露的内容；保留观看变化与动作、声音的衔接，不自行新增位移、转向或切镜。前后段换景别时，写明在什么动作发生时切镜，或摄影机怎样移动到新取景；不要将“中广景”和“近景”直接并列，让生成端猜测如何转换。满幅变分屏时写分隔线何时出现、上下格各拍谁；分屏结束时写切回哪幅画面。歌声或动作跨切镜不断，应指明不断的是声音或动作，不用尚未建立的“上屏持续”代替画面转换。

对白、独白或心声放在对应事件或表演位置，保留导演已定的发声者、逐字文本、演法及画内／画外关系；容量依据沿用[台词与同步时间](techniques/music-and-sound.md#sync-text)，实际文本或演法变化时回到该方法复核。非中文固定台词直接写目标语言原文，不用中文字符模拟发音；专业表演沿用导演已定的段落与变化。

声音设计必须交付，沿用导演已选的对白、歌唱、音乐与其他声部，不逐项补齐声部。把关键声音放在对应事件旁或集中写明关系，避免两处重复；按已定的[声部安排](techniques/music-and-sound.md#sound-plan)保留进入、让位、静默与恢复节点，编译时不另改听觉主次。

用户要求沿用既有歌曲或先前作品的配乐时，按[既有歌曲与歌词控制](techniques/music-and-sound.md#lyric-control)对照实际音乐段编译，核对曲目与段落定位、基础音乐设定、唱法及本片对白让位；不能把具体输入概括成“同款氛围”或语义不明的副歌片段。

## 表达修订与条件处理

### 表达与措辞

地点、建筑、现实对象或成熟概念的名称能够准确唤起场景时直接使用，不因知名而泛化。强 IP 的处理沿用项目约定，用户与当前 Brief 有明确要求时按要求处理。调性、速度、焦段或介质等专业参数，可按已锁定要求、选定成功写法或本片表达需要使用。

风格、类型、情绪和专业词在能准确传达选择时保留。措辞空泛时先辨认它承担什么，再决定修法：

| 词句的问题 | 怎样补足或保留 |
| --- | --- |
| 交付规格、渲染风格与赞美混在一起 | 规格核对实际可用设置；风格保留其视觉含义；同义赞美没有新增要求才删，不把风格词当作已设置的输出参数。 |
| “宏大”等词未说明所指 | 分清是空间尺度、情感分量还是其他已定体验，不能自动添人群或大场面。 |
| “动态／激烈”有强度却没有行动关系 | 写清谁在动、朝哪里、怎样变化；人物动作不自动改成运镜。 |
| “酷炫转场”没有连接办法 | 明确两镜通过形状、动作、声音还是信息相接，再写转换过程。 |
| 关键词各自准确，合起来所指不明 | 补主体、行动、对象及必要时序；互动写清对方的回应或物件的变化。 |
| “无瑕疵”或情绪词代替实际要求 | 明确本片需保持清楚的部位、状态或可见表演；不凭空增加用户未定的内容。 |

已经清楚的术语、列表和长正文沿用，不按词表删除有用选择，也不用统一字数上限删去必要过程。

中文压缩或润色后，检查省略主语及“它、旁边、先前那个、另一边、随后”等，提示词或参考图须已明确所指的行动者、对象、位置、状态和先后；有歧义时补清会改变动作含义、空间关系或后续状态的关系，背景与过场也按此判断，不必逐动作填写分解表，不凭顺口程度改动作。区分景别、构图、机位和摄影机运动：“稳定中景并缓慢推进”可指移动中保持取景，“机位固定又向前移动”则对同一阶段矛盾；“固定产品并推近”并不矛盾，先辨清固定的是对象还是机位。能从已定设计确定时忠实重写，否则指出冲突而不静默选边。去除妨碍执行的翻译腔和重复名词化，术语及其所指关系已经清楚时不扩写。固定台词、专名、素材标签和指定简繁不随润色变动；对白语域、发声语言与字幕本地化按[声音方法](techniques/music-and-sound.md#sync-text)分别处理。

### 约束与冲突

将本次需要编写的内容表达为正向、可见、可听的过程。Brief 与用户禁项必须落实和检查，但不等于逐条复制进生成正文；已由选题、角色或素材选择落实且没有相关生成风险的要求留在检查记录。反向限制只写对当前生成有具体控制作用、尚未被正向描述充分表达的内容，可放在相关镜头或结尾。

有意使用的虚化、颗粒、拖影、CG 风格或字幕应正向限定其作用范围，避免对同一对象、时段和属性提出相互矛盾的要求。修订时合并重复要求、删除已失效的约束，并核对动作、时间和前后承接。

素材或图文冲突时，按每个受控维度已经确定的依据修正相应设计或输入；图片不普遍高于文字，反向限制不能修复相互矛盾的素材，不以负面词数量判断是否需要回退，也不声称测得模型内部权重。

### 条件性适配

跨地区或受众改编时，核对笑点、关系或产品理解所依赖的手势、节日、食物、衣装与画面文字，是否仍传达所需含义；按实际影响保留、解释或替换这些载体，不只翻译台词。涉及锁定元素时说明取舍；没有这类改编任务就不增加文化审查步骤。发声语言与字幕按[声音方法](techniques/music-and-sound.md#sync-text)分别落实。

用户明确要求清晰度或排查模糊时，按[清晰度与风格约束](techniques/look-and-effects.md#clarity-control)将已定的清晰对象、对焦关系及有意柔化范围写入开头或相关镜头，核对表达是否相容。

借用外部原提示词时，保留适合本片的组织方式、风格短语与过程密度，按上文落实身份／素材绑定、当前入口条件、适配后的冲突和缺项。外部模板要求的时间码、旁观者、负向块或一格一镜不自动继承；也不因格式不同就判原稿不合格。没有作者原提示词时按已核对的成片过程自行写作，不宣称还原了原始输入。

## 视频提示词正文模板

下方框架可用于需要集中绑定角色与素材的任务；也可按当前入口使用自然段或镜头表达，不强制添加变量块。已有原稿沿用有效结构和素材绑定，用户指定格式优先；本次修改涉及绑定缺口时修正相关定义与引用。

栏目可按表达需要单列或合入相关过程，没有对应要求或已在别处表达的栏目省略；不因填模板或措辞润色新增情节、动作、镜头、光效或限制。角色与素材按本片方案定义，图片定义及对应引用按输入方案增删；需要但尚未生成的图片保留引用，未生成状态在对话中说明。

~~~text
〈仍需文字表达的画幅等要求〉

【变量定义】
{人物1}=参考图1。
{场景1}=参考图2。
{人物图}=参考图3。
{主角1}=按{人物1}的成年旅行者，面孔、身体服装与装备按图。
{主角2}=按{人物图}的成年女巫，面孔、发型、身体服装与饰品均按图保留。
〈按本轮上传清单替换示例；采用数字分身时再换成实际身份绑定〉

【全局设定】
场景布局与材质按{场景1}，{主角1}与{主角2}位于其中。
〈起始状态与必要空间关系〉

【视觉风格】
~~~

## 编译核对

对照最终正文核对以下输入事实；观看效果与表达承载按[制作包检查](production-and-delivery.md#shared-checks)判断：

- 用户锁定的内容、动作过程、摄影路径、声音、结尾和禁项仍按最新版本落实；不能仅在作品说明中存在，须在实际输入中有承载；[声音与字幕](techniques/music-and-sound.md#sync-text)的声源、原文、译文、出现时机与画内／画外关系一致。
- 当前入口的时长与选定画幅成立，使用说明中的生成比例、正文及承担构图的参考输入相容；分屏或内嵌画面按设计表达，不自动铺满最终画布。未操作的设置不记为已验证。
- 素材编号、实际引用标签、选中对象与本轮上传清单一致；完整文本包按计划编号编写，尚未生成或不支持上传的情况在对话中说明。分析依据不冒充生成输入；替换素材同步相关引用，不擅自翻译、规范化或重编号已经有效的绑定标签。
- 每个变量先定义、后使用、唯一指向；稳定身份与阶段状态分开。用户要保留的外貌要求可以表达，透明头区缺失的发型、朝向和表演信息由实际剩余输入补足。
- 按关键事件串读变量、场景与视听过程：对象是否仍是同一个，动作是否接住已定空间和状态，变化后是否正确延续。仅在定义或场景里提到要求、对应动作却没有承接其作用时，修正发生处的表达；设计本身不成立时回到制作方案。
- 正文不残留模板槽位、文件路径、准备步骤或内部检查结论。必要的保持要求可以重申，不因参考图已有某信息就禁止文字强调；同时不重复堆叠同义限制。
