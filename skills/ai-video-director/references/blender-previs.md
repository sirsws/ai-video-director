# Blender 空间预演

本文件说明如何用可修改的三维灰模验证具体拍法。是否使用与执行时机由[作品创作中的空间判断](creative.md#spatial-previs)定义，决定预演后再读本文件。

## 执行输入

以完整导演草案和已有素材为输入；已有视频提示词可辅助核对，不作为开始预演的前提。明确本段观看效果及其依赖的对象和关系；涉及互动时，确认发起、目标与响应，再选择预演区间与验证问题。简记什么可见结果支持或推翻当前拍法，已有导演稿足够时直接沿用，不另建表单。

已有认可或必须保留的图片时，按其已定用途保留身份、造型、空间结构或构图；仅在用途或用户要求锁定视角时匹配对应机位。仍须检查图片中的其他可见内容是否与走位和运镜冲突。无法从单张图确定的画外空间按导演需要补建，并标明推断。不为适配灰模静默改变用户锁定的布局和观看过程。

## 怎样做

- 默认由主 Agent 直接建模、修改与验收；委派遵循当前任务授权，不因进入预演自动委派。
- 使用本地 Blender 的 Python `bpy` 脚本后台建模和渲染；先定位并验证已有可执行文件。本地工具不可用时说明阻塞，不自动更换执行方式。
- 新建预演优先复用下方[共用基础工具](#common-tools)中适用的函数，特殊需求直接补写；已有作品小修沿用原脚本，不为统一形式迁移。
- 只建影响判断的几何、完整人偶、关键道具与真实摄影机路径。用低分辨率快速渲染，先看关键状态，再输出需要验证的运动区间；不为预演补做精细材质、面部或特效。
- 按本次验证问题保留必要的对象、目标、连接、接触与朝向，可简化外形。验证追逐关系时须包含被追目标；只检查局部净空时可省略不影响该判断的对象，并明确检查范围，局部几何结论不能替代整段观看过程检查。脚本编排的轨迹可用于检查取景与预定运动；若要据此判断通行或承接是否成立，须对照相关区间的支撑、间隙与障碍，不能只看对象最后进入目标。按问题选择侧视、剖面或其他低成本核对，不默认完整物理模拟，也不把未建模的受力、抓握或动作衔接记为已验证。
- 修改沿用同一脚本和场景，只改受影响参数。问题已经回答就结束；修改没有带来新的有效证据时，说明剩余问题并回到导演决策，不靠持续美化或暗改节奏制造通过。

## 看什么、留下什么

查看所核验动作从开始到完成的相关区间，核对人物与目标的位置、路径、遮挡和镜头衔接。核验主体轨迹或姿态时，先用固定观察位置分清主体运动与摄影机造成的变化，再用正式机位检查可辨性。几何通行与画面可读性分别核验：碰撞采样无重叠，不代表通路、目标或动作已清楚可见；参与遮挡的代理即使不计入碰撞，也须纳入目检。

试渲与中间文件放系统临时目录。采用的预演在对应作品目录 `previs/` 留下可复用脚本、`.blend`、预览 MP4 和少量关键帧。将验证问题、实际发现、采用的调整和未解决事项写回当前作品方案中的拍摄设计，并链接预演。生成输入按[统一交付格式](production-and-delivery.md#delivery)提供；只要求看拍法或只交提示词时，不因此另建制作包。不另建审批状态或要求每片填写空栏目。

<a id="previs-handoff"></a>

### 预演结果怎样进入生成输入

默认将灰模与渲染文件用于辅助制作参考图和提示词；只有本轮明确采用、当前入口支持且素材相容时，才作为生成参考输入。采用结果须落实本次判定所依赖的关系，不能停在“预演通过”或报告链接：

- 需要由图片提供的结构、相对尺度、连接与初始布局，写进相应制图提示词；已有图时核对实际图是否仍相容，需要修图就处理受影响部分。灰模可作为制图的结构依据，美术和人物造型仍按导演设计，不复制灰模人偶与材质。
- 支撑怎样维持或改变、人物与物件沿哪里运动、朝向和观察侧、切镜承接及完成后的状态，写进视频正文对应过程。将坐标和脚本轨迹转成观众能理解的关系，不复制建模参数；只有影响关键尺度或通行的数值才按需要保留。
- 有图或无图按[参考输入选择](production-and-delivery.md#reference-plan)决定；无图不免除上述表达，有图也不能让静态布局代替过程。最终按[制作核对](production-and-delivery.md#shared-checks)检查实际图与正文，设计和灰模中有、实际输入中缺的内容仍属未落实。

这些调整直接更新作品已有设计、制图要求与视频正文，不另建转交表。未检查的受力、表演或生成动态仍保留未知。何时重新验证由上层决定，沿用原脚本和场景修改受影响部分。

## 共用基础工具

[previs_common.py](../scripts/previs_common.py)提供场景初始化、基础几何、完整灰模人偶、两点连接杆、路径插值、关键帧、摄影机朝向与渲染导出；[previs_example.py](../scripts/previs_example.py)提供最小调用示例，首次使用共用工具或不确定调用方式时查阅。

- 常规变换动画中，对象创建一次，后续修改姿态与变换并写关键帧，不按每帧重建整套几何再轮换隐藏；确需逐帧几何或替换模型时例外。
- `Human.pose(position=..., yaw=..., joints=..., frame=...)`支持本片自行指定局部关节；`path_at(t, points)`按给定路径作分段线性插值；`place_link()`只画两端连接，不模拟张力。`key()`会将该对象动画槽内的关键帧插值设为线性，需要加速、缓动或其他插值时，由作品脚本编排并在调用后设置相应插值。工具不包含追逐求解、受力模拟或IK。
- 每个作品保留自己的场景脚本；确有缺口时本片局部扩展，出现可复用价值后再抽入共用文件，不为未来可能性扩建通用动作系统。
- 使用共用工具的作品，定稿时将实际使用的`previs_common.py`副本随场景脚本放在`previs/`并从同目录导入，保留当次代码版本；新作品从Skill取当前版本。共用工具升级不静默改变旧作品。
- 新建场景时在全新的Blender后台进程中调用`setup()`，它会清空当前场景；修改已有场景时跳过该函数。`render(out, temp_frames, ffmpeg=..., keyframes=...)`将`.blend`、选定关键帧和可选MP4放到输出目录；临时帧使用本次独立的系统临时目录。FFmpeg传入已定位的可执行文件，工具不自动安装。

在脚本目录运行示例：`blender --background --python previs_example.py -- --out <系统临时输出目录> --ffmpeg <已定位的可执行文件>`；其他工作目录使用脚本绝对路径。历史测试版本为 Blender 5.2.1，不代表本机当前版本；其他版本的动画API兼容性未测。示例只核验对象复用、路径与导出能运行，新的场面仍需实际查看关键区间。
