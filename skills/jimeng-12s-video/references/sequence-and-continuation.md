# 连续片段与实际接续

用于多次生成同一作品，以及下一段、续接、接尾、跨场景或修复尾部。沿用同一作品方案，各段在[作品创作](creative.md)中共同设计内容与声画，再落实输入；不为每段重做候选或填写一套重复的创意表。

入口：[全片安排](#plan) · [实际接续](#reconcile) · [接法选择](#join) · [最小记录](#record) · [故障定位](#repair)。

<a id="plan"></a>

## 先确定全片与本段任务

全片先定观看目标和最终回报，给每段一个具体作用及停止点。按当前入口的单次时长分配过程，不把广告、舞蹈、对白或多镜头自动判为必须拆片。只在用户要求多段，或完整过程确需多次生成且已获得相应授权时分段。

写明全片共用的身份、衣装、关键道具、空间和参考来源；确定摄影、光色、节奏及声音哪些贯穿，哪些随推进改变。渐近的景别、逐渐开放的空间或由单声部到合奏等变化，要有段间作用，不能只写“统一风格”。二维作品同时保持角色画法、线宽、色板、图层关系与运动节奏。

用户明确要求多个版本，且它们共享同一过程时，可先划出共用段与各版独有的决定或结局；按实际状态连接对应变化段，逐版核对重复、漏掉的事件与接点。

各段只记录自身任务、关键起止状态、变化与承接。同一作品可以交替使用叙事和非叙事段落；展示或观察段不强加心理冲突，也不自动重置前段已成立的关系与尚未解决的叙事任务。把事件分为“已发生／本段发生／以后发生”，同一事件的实际完成情况更新后，后面的安排也要更新。每段结束服务于全片，不自动加独立收尾、回中性姿态或完整落幕。

用户要求一次写完整片时，交付全部段落的暂定正文，注明后段依据的是计划起点。尚无前段实际结果时，不能宣称已核对接续；这个缺口不阻止交付全片草案。

<a id="reconcile"></a>

## 从实际采用状态接续

1. **明确采用依据。** 使用用户已选定的成片、尾帧或明确描述，记录具体文件或信息来源。多个版本未指定且差异会改变接法时，先确定采用哪一份；不采用的版本不进入后续事实。
2. **读取能看到的内容。** 按[参考视频查看方式](reference-videos.md#查看方式)核对尾部及必要前文，提取站位、朝向、持物、开合、空间、光色和构图。静帧不能证明速度、动作阶段或声音；材料不可查看时引用用户描述，不冒充目检。宿主不能审听时，听感采用用户明确反馈。
3. **核对改变接法的差异。** 比较计划与实际：关键事件是否完成，未完动作朝哪里继续，镜头在移动还是已停，声音停在哪个乐句或对白阶段。人物意图和潜台词属于创作判断，不能当成从尾帧直接读出的事实。
4. **决定沿用或修正。** 用户接受的偏差成为本次后续起点；未锁定的执行细节可在授权内顺势调整。改变核心回报或用户硬要求时说明取舍。需要修前段时，后段仍以当前采用版本为依据，修订完成后再更新关联段落。
5. **重排后续并编译。** 已经完成的事件不重演；提前发生的后续事件从原位置删除或改为新的发展；未完成的重新安排。稳定身份仍用原身份源，起始动作和道具状态用实际采用结果。编译本段自己的开场、推进与停止点，给以后保留的事件不提前兑现。

只询问会改变接法、且不能从可访问材料中确认的信息。明确用户描述已足够时直接继续，不要求补齐整张记录表。文字接续、尾帧输入和视频延长是不同执行方式：只能调用当前入口确实支持的方式，不凭“连续”二字假设可以上传视频或音频。

<a id="join"></a>

## 选择接法及其代价

| 接法 | 本段须确定的内容 | 边界与取舍 |
| --- | --- | --- |
| 同镜头续接 | 尾部构图、运动方向和阶段、机位与光色、未完声音的接入点 | 只在可用素材及入口支持时追求帧间接合；文字相同不保证无缝。 |
| 有意切到下一镜 | 新取景、切点、动作或声音承接、重新定位线索 | 可保留故事与动作连续，不承诺逐帧相同；不能切掉必须看见的过程。 |
| 两个已知状态之间补过程 | 起点、终点和必须经过的动作或因果 | 已知两帧不证明中间有足够时间或空间，先设计过渡再编译。 |
| 修复前段尾部 | 保留到哪个可靠节点、从哪里重做、后续哪些依据失效；当前入口与本次范围支持时，可从最后可靠帧派生下一必要动作状态图，用于重做受影响尾段 | 保留已有效的前段；新图若已跨过动作，应补过渡或有意切镜，但不能省掉必须看见的过程；静图不证明动作连续。替换尾部后重新核对接点与下一段起点。 |
| 漂移后重新建立 | 回到可靠身份与场景参考，选择新的建立画面或明确切镜 | 可能失去连续镜头感，说明损失；根据实际漂移判断，不按固定接续次数强制执行。 |

复杂转换难以保持同一追踪对象时，可先设计载体位置、比例与附着关系均可辨的中间态，再安排起点到中间态、由实际采用的中间态到终点。只有本轮允许多段、输入方式支持且接合收益值得成本时采用；不能把计划中间态当成已经生成的起点。

## 连续作品的最小接续记录

多段作品的生成输入按[统一交付格式](production-and-delivery.md#完整交付-md-模板)及片段编号组织。下方信息项用于全片安排和实际接续核对，在对话或已有接续记录中按需确认，不固定附入交付内容；单片不生成空表。共同设定写一次，各段只补自身变化。

```markdown
## 【连续片段总览】
全片目标与结局：
共用身份、资产和视听处理：
段1：观看任务；计划起点 → 停止点；随后还要发生什么。
段2：观看任务；计划起点 → 停止点；随后还要发生什么。
各段正文依据：计划起点／已核对采用结果；按实际填写。

## 【实际接续记录】
采用依据：具体文件或用户明确描述；说明哪些已查看、哪些是用户报告。
实际结束：只写影响下一段的位置、持物、形态、动作、镜头、光色和声音。
与计划的差异及处理：采用／采用并调整后续／需修／不采用，附决定依据。
事件更新：已完成；本段要做；留到以后。
尚缺的信息与影响：没有影响接法的缺口则省略。
```

跨会话继续时，读取已有接续记录或可访问的原对话，确认共用设定、当前采用片段、实际状态与下一段任务，不以隐藏记忆代替已核对来源；已经结束的场景只保留影响后续的结果与采用依据，历史尝试不挤入当前执行说明。计划与实际分开，不回改旧计划冒充早已预见。采用新版后更新当前依据，旧版本只保留必要溯源，不与当前执行状态混排。交付完成与登记按[项目主流程](../SKILL.md#delivery-status)执行。用户要求将实际片段拼接成片时，[后期执行](post-production.md)读取同一份采用依据、源文件与接点，不重新编造各段已实现的事件。

<a id="repair"></a>

## 接续故障定位

| 实际症状 | 优先核对的可能原因 | 最小修正 |
| --- | --- | --- |
| 重演出门、递物或对白 | 后段仍引用旧计划；全局描述包含已完成事件 | 替换起点并删除重演要求，保留本段新任务。 |
| 后面的高潮提前发生 | 本段正文写入了未来事件；参考图已露出结果 | 缩小本段范围或换参考状态；用户已接受提前发生时重排以后。 |
| 动作或镜头重新起步 | 结束阶段未继承；默认收束把运动停掉 | 写明实际方向与阶段，或采用有意切镜并说明变化。 |
| 道具复原、换手或身份漂移 | 初始全局设定覆盖后态；身份源和状态源冲突 | 将稳定身份与当下状态分开，必要时更换参考或重新建立。 |
| 声音重复或断层 | 计划乐句与用户确认的实际声音不一致 | 按已知阶段安排进入与让位；未知听感不靠想象补齐。 |

这些是待核对的原因，不是症状与原因的一一对应。修改后检查本段以及真正受影响的后段；声称提高稳定性时说明消除了什么冲突，不把预测当实测。
