# 生成准备、检查与交付制作包

承接[作品创作](creative.md)已形成的同一方案，落实参考输入和最终提示词。已有内容可以在发现缺口时继续完善，不另起一轮选题或独立导演稿。

按当前工作定位：[参考输入](#reference-plan) → [提示词落实](#compile) → [制作包检查](#shared-checks) → [交付](#delivery)。返修直接查[问题处理](#repair-decision)，只处理受影响部分。

<a id="reference-plan"></a>

## 参考输入方案

先读[图片用途与取舍](reference-images.md#reference-selection)，比较文字、已有资产和新图分别能支持什么。用图与图数由本片的身份、造型、空间、状态或构图需要决定；不默认每片都出图，也不因纯文字方便就省掉确需的输入。已读且足够的选择依据直接沿用。

每份输入列明：**本次编号/变量、用途、必要的不继承内容**；实际存在时附文件，复杂场面再补适用时段、选中对象或状态。仅供分析的原作不列入上传清单；其他媒介须核对当前入口确实支持，不虚构音频/视频上传步骤。

| 输入状态 | 清单与使用说明 |
| --- | --- |
| 无需参考图 | 省略图片条目，保留生成画幅与必要使用说明，注明无需上传。 |
| 需要但尚未生成 | 列图片计划、完整制图词与正文引用，标为未生成；不虚构实际文件或目检通过。 |
| 已有素材 | 列实际文件与上传顺序/变量，按实物核对用途和作品安排，确定是否采用。 |

稳定身份、造型与当前动作状态分开：数字分身或衣装图负责身份/服装，实际采用的前段画面负责当前持物、方位和行动阶段。参考中的动作/运镜供体只承担本次选择的作用。多对象用实际方位、衣装等可见特征指认，不能把供体的角色设定一并搬过来。

### 实际素材与作品安排相互校准

实际查看图片后判断它能否支持本片；先前检查且文件未变时可复用。两图冲突或图文冲突时，选定来源、缩小参考用途、换图或修图，不能靠写“忽略”就认定冲突消失。图中不见的运动和声音仍要写入正文。

- 多格图先核对[格间关系](reference-images.md#grid-meaning)：顺序分镜、设定多视图与同时分屏不是同一用途。顺序分镜出图后做[逐格校准](reference-images.md#出图后逐格校准)，格数不自动等于镜头数。
- 从视频借动作或摄影，按[参考视频](reference-videos.md)实际查看；分别确定人体过程和摄影路径。新角色比例、衣装或装备改变活动范围时，保留动作意图与关键接触，重新安排够取距离和落脚。
- 静态效果图承担关键状态参考时，按其用途设计怎样到达、变化或继续，不把摆到图中姿势当整段作品。
- 生图、编辑与完整头区透明处理按[参考图制作](reference-images.md)的相应要求执行。

素材改变后，按“实际输入关系 → 受影响作品决定 → 正文 → 原检查结论”同步更新，保留无关的动作、摄影与声音。改变了关键空间关系时，回[空间判断](creative.md#spatial-previs)复核；已采用预演的调整落实到真实图或正文，不以预演文件代替生成输入。

<a id="compile"></a>

## 提示词落实

首次编写或整体重写时，按[提示词编译](prompt-compiler.md)形成可直接复制的正文；已有稿局部修改按[局部返修](#local-revision)处理。

将已定的动作、摄影、声音与固定台词/歌词/字幕落实到实际输入；静态图提供外观或状态，动态与声画过程由正文承接。

正文或输入变化后，按[制作包检查](#shared-checks)复核；已有稿修改同时核对删改，发现设计缺口时回到同一方案修正。

<a id="shared-checks"></a>

## 制作包检查

作品创作检查“照方案实现是否值得看、符合要求”；本节检查“真正交给生成器的输入是否承载了它”。对照用户要求与作品方案，检查最终正文、绑定及输入清单；检查结论须与素材实际状态相符。

| 对象 | 具体看什么 | 缺口返回哪里 |
| --- | --- | --- |
| 内容、过程与回报 | 主要行动/体验有必要的中间过程和可读后果；时间没有被无作用铺垫或收尾挤掉；明确要求没有只留在说明中。 | 同一作品方案的相关段落，或遗漏的正文。 |
| 观看与声音 | 按正文写定的景别和画面边界，核对本段承诺可见的身体、物件、动作起止、接触点与落点是否真能入画；“完整保留”不能覆盖具体取景矛盾。再核摄影路径、焦点、光色和声部时机是否共同支持本片。 | 用[景别与取景](techniques/camera-foundations.md#shot-selection)改观察位置或画面边界，保住关键过程，再同步正文；其他声画问题定向查专项。 |
| 连续与输入 | 实际图的身份/状态/空间与正文相容；图号、变量、上传文件真实一致；跨镜/跨段关键状态接得上。 | 相应素材、绑定或[实际接续](sequence-and-continuation.md#reconcile)。 |
| 硬约束与交付 | 当前入口、用户固定台词/歌词/字幕/禁项、本次采用的身份绑定、Brief 与本轮文件范围均有真实落实。 | 对应输入或交付材料；有专项工作流时再按其要求核对。 |

不因表格有一行就为本片增加无关内容。具体速度、表演、摄影、声音或空间难点使用对应方法；术语出现、栏目齐全、句法完整和内部自评不能证明观看效果。

<a id="已知缺口与执行未知"></a>

### 可交付条件与证据边界

关键行动/摄影/声音尚未安排、两个条件冲突、按现稿实现也缺核心体验，是需要先修的缺口。安排具体且相容，但动态自然度、身份、口型或音色尚未实生成验证，是执行未知；不能按已经发生的失败处理。

“可交付”指本轮范围内输入齐备、设计有依据且无已知阻断项。限定范围的文字稿只标明该范围完成；转为正式制作包时，按当前请求和项目约定重新核对角色、输入与缺少的资产，不继承试用时临时指定的虚构身份或不出图条件。

字幕、混音、拼接等若只能在实际视频后完成，在对话中说明后期所需素材和操作即可，不能写已经完成。当前制作包完成不代表成片、听感或传播验证通过。

检查意见必须指出位置或证据、影响哪项要求、当前缺什么、应修哪里。没有新问题可以维持原稿；“再检查”不意味着必须改稿。目标、输入与证据未变且无漏检时复用有效结论。

有待修问题时写具体缺口，修完后替换当前结论，不并列保留失效判断。证据指向真实正文或素材，少量决定性依据即可，不逐条重抄剧情。

<a id="delivery"></a>

## 交付与记录

制作输入统一按以下顺序交付：

1. **视频提示词：** 可直接复制的完整当前正文；生成画幅等需要用户设置的参数，在正文前简要标注。
2. **制图词：** 本轮需要生成或编辑图片时，逐图给完整可粘贴文本；仅复用已有图片时，无需重复附历史制图词。
3. **参考图链接：** 有实际图片时按上传顺序提供链接及必要预览，注明用途、格号或引用对应；尚未生成的图片不造链接。

无需制图或没有实际图片时，省略相应项，不留空栏目。创作与检查照常完成，关键取舍、检查结论、实际生成/编辑调用次数及未解决事项在对话中简述，不固定附方案或核查章节；图数不等于调用次数。

不强制另建“完整交付主文件”。需要保存或导出时，一份 `<作品名>.md` 只承载上述内容；已有文件直接更新，不默认另存同内容副本。用户明确需要独立文件时再导出。完成后的登记与状态按[项目主流程](../SKILL.md#delivery-status)执行。

<a id="完整交付-md-模板"></a>
<a id="主文件默认组织"></a>

### 统一交付格式

~~~markdown
# 《作品名》

## 视频提示词
生成画幅：（需要设置时填写）
（可直接复制的完整视频正文）

## 制图词
（本轮需要时，按图号列完整生成或编辑提示词）

## 参考图链接
（已有实际图片时，按上传顺序列链接及必要用途或引用对应）
~~~

连续作品按片段编号组织上述三项，计划与实际采用状态分开，接续依据按[最小接续记录](sequence-and-continuation.md#record)核对。旧稿的“最终创意”和“拍摄设计”仍作为同一方案的既有内容参考；局部修改沿用有效内容，不批量改名、迁移或删除历史文件。

<a id="repair-decision"></a>

## 问题处理与复核

先分清本次依据：文字已知遗漏、实图冲突、实际视频可观察缺陷、用户明确反馈，或尚未证实的原因假设。真实结果按[视频查看](reference-videos.md#查看方式)取证；需要解释原因时再查制作材料。稀疏抽帧不能证明整个动作成功，音轨参数不能证明听感。

| 处置 | 适用依据 |
| --- | --- |
| 保留 | 要求和核心过程成立；差异不损害目标，没有新的阻断项。 |
| 补正文/改表达 | 有遗漏、歧义、互相矛盾或引用错误；保住有效行动与声画关系。 |
| 改素材/局部重出 | 实图身份、状态、空间不适配；按授权修相关图或一段，不声称生成式修改保住其余像素。 |
| 接受偏差并继续 | 用户采用了实际结果，或授权内差异可沿用；更新真实起点与后续，清除已发生事件，不能假装旧计划已实现。 |
| 用实际素材后期修整 | 现有素材已包含所需过程，可通过选段、重排、字幕或声音处理完成；进入[后期执行](post-production.md)。 |
| 保持输入再试、换实现或停止 | 没有证据证明提示词错误，或现有路径不能兑现要求；说明理由与影响。生成由用户还是工具执行，沿用本轮范围，不把重试设为必需步骤。 |

<a id="local-revision"></a>

### 已有稿的局部返修

以本次修改所针对的原稿为底，只改目标及必要衔接；未受影响的有效句段、结构和具体声画安排沿用，不顺手整篇润色、压缩或重套模板。动作、取景、时序、拟音或素材引用确需联动时一起修，并同步受影响的方案和检查结论。用户要求整体重写时按其范围处理，不把局部保留规则套到全面重做。

交付前对照改前改后的实际内容，核对新要求落实与原有内容保留，撤回与本次要求或已定位问题无关的删改。重读受影响完整段落及前后承接；替换安排时确认原作用如何承接，需要删除时说明依据，不能以故事大意还在代替核对。

只回到问题所在决定。若必须改变用户锁定内容或范围，说明具体取舍再交由用户决定；其他授权内可定位的问题继续修，不加新的阶段审批。只有执行未知而无矛盾时，不为“稳”提前静态化。

收到平台拒绝，区分平台明确理由、用户描述与原因假设；“生成失败”不足以判定过滤原因。忠实澄清与改变内容分开，无新证据不反复替换同义词，不把单次拒绝升级成通则。

为了区分原因的试验尽量只变一个相关条件；同时修多个明确冲突可以，但不归因给某一项。没有新证据或有效修法且核心缺口仍在，保留未解决，不能无限追加规则或降低标准称完成。

需要完整推导示例时，按[示例索引](examples.md)选择厨房告别、共同踏舞、二维过程或实际接续；它们是设计示范，不是默认剧情或成功率证据。
